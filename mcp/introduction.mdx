The GreenTick MCP server lets an assistant use your WhatsApp Business account. It calls the Developer API with your API key. You describe the job in plain language. The assistant discovers the tools, calls them, and reports the result.

The server address is `https://api.greentick.ai/mcp`. Connecting it asks you to sign in as the GreenTick account owner. A Developer API key cannot open this connection. That host is the WhatsApp server. The `/mcp` path on this docs site is a separate search server for the documentation, and it cannot send WhatsApp messages.

The server is included on Starter, Standard, and Premium. An expired plan rejects every tool call with `PLAN_EXPIRED`.

## How it works

```mermaid
sequenceDiagram
    participant You
    participant Agent as AI assistant
    participant MCP as GreenTick MCP
    participant API as Developer API

    You->>Agent: Ask in plain language
    Agent->>MCP: Tool call with the signed-in account
    MCP->>API: Matching API request
    API-->>MCP: Result
    MCP-->>Agent: Tool result
    Agent-->>You: What happened, or the error
```

GreenTick sends a fixed set of instructions with the server. The assistant does not send, publish, schedule, enroll, or enable anything until you ask for that action in the conversation. Those stop conditions are written out in [Rules](/mcp/rules).

## Authentication

Add the server in Claude, Cursor, VS Code, or Claude Code. The client sends you to GreenTick to sign in. Only the owner of the WhatsApp Business accounts can finish that screen. One sign-in covers every account that owner owns. The consent screen asks which account to use when a message does not name one.

A `gt_live_` Developer API key is rejected on `https://api.greentick.ai/mcp`. Those keys still work on the Developer API at `/v1`.

Client steps are on [Client setup](/mcp/client-setup).

A request to `https://api.greentick.ai/mcp` without a signed-in session returns `401`. That response is what starts the sign-in.

## Quick example

Ask:

```text
List my approved WhatsApp templates and tell me the name and language of each one. Do not send anything.
```

A connected assistant calls `list_templates` and returns the approved set. Sending one of those templates is a separate request, covered in [Send an approved template](/mcp/use-cases/send-approved-template).

## FAQ

<AccordionGroup>
  <Accordion title="Does the assistant send WhatsApp messages on its own?">
    No. `send_message`, `schedule_broadcast`, `publish_workflow`, `publish_flow`, `send_flow`, `enroll_automation`, and `enable_ai_bot` run only after you ask for that action in the conversation. Reading tools, such as `list_templates` and `list_contacts`, do not need a separate yes.
  </Accordion>
  <Accordion title="The Integrations card says MCP is coming soon. Can I connect anyway?">
    Yes. Add `https://api.greentick.ai/mcp` and sign in as the account owner. You do not wait for that card. See [Client setup](/mcp/client-setup).
  </Accordion>
  <Accordion title="What happens when the plan expires or the sign-in ends?">
    An expired plan returns `403` with `PLAN_EXPIRED`. The assistant does not retry until you renew on **Manage Plan**. A missing or expired sign-in returns `401` with `UNAUTHORIZED`. Connect the server again and sign in.
  </Accordion>
  <Accordion title="Do I need a separate model API key?">
    No. Claude, Cursor, or whichever client you use provides the model. GreenTick checks the sign-in from the connect screen.
  </Accordion>
</AccordionGroup>
